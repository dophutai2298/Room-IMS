# 09.1 — Enhance Tenant Profile and Directory Management

**What to build:** Expand Tenant management from a room-scoped helper into a full Tenant profile and directory workflow. Users can manage Tenant identity details, upload multiple CCCD images, delete Tenants safely, and use a dedicated `/tenants` page to search, view, create, update, and delete Tenants across all Rooms.

**Blocked by:** 09 — Tenants Client Data Management.

**Status:** Done

## Tenant Profile Requirements

- [x] Tenant create and update forms support full name, phone number, date of birth as text, permanent address, CCCD number, and Tenant status.
- [x] Full name, phone number, and CCCD number are required before a Tenant can be saved.
- [x] Tenant status remains limited to `Active` and `Moved Out`, displayed in Vietnamese as "Đang ở" and "Đã chuyển đi".
- [x] Tenant detail data persists and renders safely after refresh from the authenticated app API.
- [x] Existing Tenant records without the new optional fields continue to load without breaking UI.

## CCCD Image Upload Requirements

- [x] Tenant create and update flows support uploading multiple CCCD images.
- [x] Uploaded CCCD images are associated with the Tenant and are visible from Tenant detail.
- [x] Users can add more CCCD images when editing a Tenant.
- [x] Users can stage storage-backed CCCD images for removal from the Tenant edit form, with the actual InsForge delete happening only when saving changes.
- [x] Newly selected profile images render immediately in the Tenant image gallery as unsaved previews.
- [x] Upload validation handles empty files, unsupported file types, oversized files, saving states, success states, and API errors.
- [x] Existing `cccd_front_url` and `cccd_back_url` data remains readable during migration, even if the new upload model supports more than two images.

## Tenant Delete Requirements

- [x] Users can delete a Tenant from the room-scoped Tenant UI when the Tenant is safe to delete.
- [x] Users can delete a Tenant from the `/tenants` management page when the Tenant is safe to delete.
- [x] Delete actions use a confirmation step and clear success/error states.
- [x] The API prevents deleting a Tenant that is still referenced by an active Contract as Key Tenant.
- [x] Successful deletes invalidate Tenant list, Tenant detail, Room detail, Room list, Contract, Invoice, and Dashboard query keys where they can be affected.

## `/tenants` Directory Requirements

- [x] A dedicated `/tenants` page lists all Tenants in a table.
- [x] The Tenant table supports loading, empty, error, retry, and refreshed-data states.
- [x] Users can search Tenants by name from the table.
- [x] Users can open Tenant detail from the table.
- [x] Users can create, edit, and delete Tenants from the `/tenants` page.
- [x] Tenant rows show enough context to manage them globally: Tenant name, phone, CCCD number, status, assigned Room, and whether they are the current Key Tenant.
- [x] Creating a Tenant from `/tenants` requires selecting the Room that the Tenant belongs to.

## API and Data Architecture Requirements

- [x] Tenant reads and writes continue to use TanStack Query through authenticated app APIs.
- [x] Tenant list APIs support both room-scoped reads and global directory reads.
- [x] Tenant search by name is handled by the app API contract, not by direct UI access to InsForge.
- [x] Tenant create, update, delete, CCCD upload, and CCCD image delete flows go through service and repository interfaces before reaching the InsForge adapter.
- [x] Database migration adds the missing Tenant profile fields and the storage/linking model needed for multiple CCCD images.
- [x] API timing logs identify Tenant list, detail, create, update, delete, search, upload, and image delete durations.
- [x] A smoke test or behavior test verifies Tenant profile validation, global Tenant search, safe delete behavior, and CCCD image association for an authenticated Landlord or Staff user.

## Implementation summary

- Added Tenant profile fields: `date_of_birth`, `permanent_address`, `cccd_number`.
- Added `tenant_cccd_images` table for multiple CCCD image metadata while preserving legacy `cccd_front_url` and `cccd_back_url`.
- Added authenticated APIs:
  - `GET/POST /api/tenants`
  - `GET/PATCH/DELETE /api/tenants/[id]`
  - `POST /api/tenants/[id]/cccd-images`
  - `DELETE /api/tenants/[id]/cccd-images/[imageId]`
  - existing `GET/POST /api/rooms/[id]/tenants` now returns and saves the enhanced profile shape.
- Extended Tenant service/repository/InsForge adapter for global search, detail, create, update, safe delete, storage-backed CCCD upload, and storage-backed CCCD image delete.
- Added shared Tenant management components for create/update/upload/delete/gallery.
- Added an edit-only X overlay in `TenantImageGallery` so users can stage storage-backed image removals while editing a Tenant.
- Added gallery previews for newly selected profile images before upload; staged image removals and new uploads are synchronized only after the user clicks save.
- Upgraded room detail Tenant card to show CCCD/profile fields, image gallery, upload, and delete action.
- Added `/tenants` directory page with table, search by name, create/edit/delete, and detail dialog.
- Added Tenant navigation and protected `/tenants` route.
- Updated Tenant API contract and service behavior smoke coverage for profile validation, directory search, safe delete, CCCD image upload, and CCCD image delete.
